## 0. 产品重心（最高优先级设计输入）

**以渠道为主。渠道是全 App 的前置依赖**：不连接渠道，通知不会流动，Agent、历史、诊断、总览全部失去意义。设计处处体现这一点：

1. **导航优先级**：渠道 → Agent 管理 → 总览 → 历史 → 诊断 → 设置。
2. **空态漏斗**：任何"没有数据"的页面，首要动作都是引导**连接渠道**（主 CTA 指向渠道页），而不是空洞的"暂无数据"。
3. **总览 KPI 首位锚点 = 渠道账号健康**（在线 / 等待登录 / 失效），Agent 接入次之。
4. **实施顺序渠道先行**：渠道页 → Agent → 总览 / 历史 / 诊断 → 设置。
5. 页面文案直接讲因果（如历史页空态："连接渠道并触发通知后，这里才会出现投递记录"）。

> 说明：路由路径（`/channels`、`/agents`、`/overview` …）与落地路由不变，只调**导航顺序与内容优先级**。若你更想保留"总览"在导航首位，说一声即可改（本条是唯一可回退的 IA 决策）。

## 1. 设计原则（新思考，替代旧技能书）

1. **灰度先行，颜色后置**：层级先靠字号 / 字重 / 间距 / 位置建立；颜色只做强化，且不独自承载语义（状态=色+文字/图标冗余）。
2. **一屏一锚点**：每屏只有一个视觉锚点（大数字或主标题），其余降噪；禁止"全都又粗又亮又带框"。
3. **间距即分组**：组内 `--space-2`(8px)、组间 `--space-5/6`(24/32px)，悬殊到不可能误读"谁跟谁一类"。
4. **字阶少而差大**：`28 / 18 / 14 / 12` 四档（展示值 / 区标题 / 正文 / 标签），替换现在的 20/16/14/13/12 五档贴排。
5. **少边框、多表面差**：去通栏细线，用卡片表面差、留白、1px 微光描边分区；elevation 只有 4 档（0 内容 / 1 卡片 / 2 浮层 / 3 模态）。

## 2. 气质档位：B｜中庸点缀（已定）

卡片常驻微光描边 + 柔和玻璃；hover 才抬升发光；青色点缀稳定但不抢层级。**发光预算（白名单）**：主按钮常驻微光、hover 抬升发光、`focus-visible` 聚焦环、状态徽标呼吸（仅 warning/danger/异常）。

**状态徽标呼吸微光（档位 1 · 已定）**：仅 danger / warning / 异常态徽标；周期约 2.5s、幅度极低；**暗色 = 辉光脉冲，亮色 = 极淡阴影脉冲**（亮色零辉光原则下用阴影表达）；成功 / 正常 / 计数态完全静止；`prefers-reduced-motion` 全关。语义由「颜色 + 文字」承担，动效仅作注意力引导、不承载信息（去掉不丢信息）。mockup 标注写法统一为「失败 ｜ 动效：呼吸微光」，禁止把动效词写进文案位。

## 3. 明暗双主题（两者都是一等公民）

- **架构**：语义角色 token 不变（canvas / surface / surface-muted / border / text / text-muted / accent / state-* / soft-* / glass-* / border-* / glow-*），`:root[data-theme="dark"]` 与 `:root[data-theme="light"]` 各一套值；组件只消费 `var(--*)`，零硬编码。
- **暗色**：现有一套为基线，按气质 B 微调（发光预算收敛）。
- **亮色（专门设计，严禁机械反色）**：
  - 毛玻璃 → **"白面 + 1px 冷灰细边 + 淡阴影"**（elevation 1/2，如 `0 1px 2px rgba(16,24,40,.06)` + `0 4px 12px rgba(16,24,40,.05)`）；`backdrop-filter` 关闭（浅色下玻璃易脏）。
  - 发光 → 收敛为**深色描边高亮 + 阴影抬升**；hover 用阴影而非辉光；聚焦环改 2px 深青描边。
  - 主色 → **深青**（`#0e7490` 级），替换暗色的亮青 `#2ee0f0`（亮青在白底上对比度不合格）。
  - 柔和底 → 加深饱和（约 12% 深色调叠加），语义色整体取暗一档，逐对核算 ≥4.5:1。
  - 画布 `#f5f7fa` 级、面 `#ffffff`、文本 `#1a2230` 级、次级文本 `#5b6675` 级（最终值以逐对对比度核算为准，落 `tokens.css`）。
- **切换**：导航底部三段控件「明 / 暗 / 跟随系统」+ localStorage 记忆；默认**跟随系统**（`prefers-color-scheme`）。
- **验收**：两套主题都要过 axe 对比度；视觉回归扩成**双主题截图矩阵**（6 页 × 2 主题基线）。

## 4. 页面范式（六页按工作类型选范式）

| 页面 | 工作类型 | 范式 | 结构要点 |
| --- | --- | --- | --- |
| **渠道** | 列表 + 详情（+强引导） | Master–Detail | 渠道卡带 → 账号行卡 → 详情四段（身份 / 健康 / 配置 / 测试）；空态 = 全 App 最强引导 |
| Agent 管理 | 列表 + 详情 | Master–Detail | 行卡列表（标题 / 元信息 / 状态）+ 右详情三段（身份 / 能力 / 配置） |
| 总览 | 监控仪表盘 | Dashboard | KPI 锚点带（渠道健康居首）→ 例外面板 → 投递流（时间分组） |
| 历史 | 检索报表 | Filter + Table | 筛选带（主筛选一行、次筛选折叠）→ 固定轨道表 + 详情面板 |
| 诊断 | 例外分诊 | Exception Triage | 按严重度分组 + 可执行动作行 + 迁移卡 |
| 设置 | 配置中枢 | Settings | 左分组目录（sticky）+ 右分组面板（一决策一行） |

## 5. 关键页设计

### 5.1 渠道页（第一优先）
- 页头：标题「渠道」+ 因果式说明（"连接通知渠道；不通渠道，Agent 与历史都不会有数据"）+ 主操作「添加渠道账号」。
- **渠道卡带**：每个渠道一张卡（名称 + 账号数徽标 + 健康点），卡内是账号行卡。
- **账号行卡**：账号名（可长文本截断）+ 健康徽标 + 最近错误摘要（有则一行）+ 快捷操作（测试发送 / 重新登录）。
- **右详情**（选中账号）：身份 / 健康与错误 / 配置 / 测试发送 四段，段间 24px。
- **空态（无账号）＝ 全 App 最重要空态**：锚点大标题「先连接渠道」+ 三步说明（选择渠道 → 扫码登录 → 验证投递）+ 主 CTA「添加渠道账号」。
- 登录对话框（二维码 / 验证码流程）**流程逻辑零改动**，只重排视觉（模态玻璃 + 1px 微光边 + 底部操作区矮窗内部滚动）。

### 5.2 设置页
- 左：六组目录（通知 / 回复 / 静默时段 / Agent 默认 / 更新 / 数据），sticky，当前位置高亮；右：当前组的分组卡。
- 分组卡 = 标题 + 一句话说明 + 行列表；**一决策一行**（标签+说明在左、控件右对齐成列），勾选框不再飘到最右边缘。
- 数值类字段用等宽两列（勿扰开始 / 结束），消除参差。
- 保存状态常驻可见（"已保存 / 有未保存更改"）；危险操作（若有）独立成组。

### 5.3 总览页
- KPI 带 4 张等宽卡（28px 数字 + 12px 标签 + 状态点）：**渠道账号健康（首位）**、Agent 接入、运行状态、待处理。（只用现有数据直接可得的指标，不发明新度量）
- **例外面板（需要处理）置于投递流之前**：监控范式=先看要处理什么。
- 投递流按「今天 / 昨天」时间分组，行内标题 / 摘要（1 行截断）/ 相对时间 / 状态徽标层级严格。

### 5.4 Agent / 历史 / 诊断
- Agent：行卡列表 + 三段详情；长文本换行或省略，禁止断字（`word-break: keep-all`）。
- 历史：筛选带收拢（主一行、次折叠、重置并入行尾）；表格固定列轨道 + 中文不断字；虚拟列表容器明确高度、行底透明防白闪；详情面板与列表底部对齐。
- 诊断：按严重度（错误 / 等待 / 正常）分组，动作行右对齐，迁移卡独立成组。

## 6. 交互与状态

六态闭环（Default / hover 抬升 1px / active 触底 `scale(.98)` / `focus-visible` 2px 发光环 + offset 2px / disabled 0.45 + `not-allowed`（表单用 muted 双值保对比度）/ Loading 骨架 1:1 防 CLS）。空态、错误态、加载态三态齐全且**按第 0 节漏斗原则写文案**。动效 token 化（120/150ms + ease-out），`prefers-reduced-motion` 全降级。

## 7. 工程边界与红线

- **零改动**：业务逻辑、数据结构、数据请求、TanStack Query 缓存 Key、表单提交逻辑、路由路径、业务状态机、`src/bridge/**`。
- **可改动**：DOM/JSX 结构、信息架构与导航顺序、样式、文案层级（**可访问名与 role 尽量原样保留**——它们同时是无障碍契约与测试契约，如「添加渠道账号」「关闭登录窗口」「全局暂停」、`role="switch"`、h2「… 详情」等）。
- **测试**：DOM 重组牵动的选择器同步更新，断言意图不变（可访问名 / 无裁切 / 无溢出 / 无重叠 / 键盘顺序与视觉顺序一致），全部必须跑绿。已知需同步：`navigation.spec.ts` 的 Tab 顺序断言（导航重排后）、视觉基线（双主题矩阵）。
- 工程底线：4/8px 间距网格、无魔法数字（一律 token）、对比度 ≥4.5:1、focus-visible 可见、reduced-motion 降级。
- 门禁：`typecheck` / `test` / `build` / `test:a11y` / `test:visual` / `test:e2e` 全绿；仓库级 `go test ./...`、`go vet ./...`、`gofmt -l cmd internal` 复核。
